Entra ID Passkey Sign-In with Nonattestable Authenticator AAGUID

Last updated 7 days ago on 2026-11-20
Created a month ago on 2026-10-22

About

Identifies a successful passkey or FIDO2 authentication step in a Microsoft Entra ID sign-in whose Authenticator Attestation GUID (AAGUID) is all zeros or is not a well-formed UUID. Platform and hardware authenticators report a vendor AAGUID registered in the FIDO Metadata Service, so a zero or malformed value indicates a software authenticator or a custom WebAuthn implementation. Offensive tooling such as ROADtools roadtx and DSInternals.Passkeys can register shadow passkeys with any AAGUID, including legitimate vendor values, so this rule catches only the unconfigured or careless case. Treat it as a corroborating signal alongside non-portal passkey registration.

False Positive Examples
WebAuthn clients may replace the AAGUID with zeros when attestation conveyance is "none", and test or custom WebAuthn implementations can present zero or malformed AAGUIDs. Confirm the user registered the passkey, review the registration audit event for the initiating application, and verify the sign-in context (source, device, timing) before escalating. Enforcing FIDO2 attestation and AAGUID key restrictions prevents such credentials from being registered at all.

Query

✄𐘗FROM logs-azure.signinlogs-* METADATA _id, _index, _version
| WHERE azure.signinlogs.category == "SignInLogs"
    AND azure.signinlogs.properties.authentication_details IS NOT NULL
| EVAL ad = TO_STRING(azure.signinlogs.properties.authentication_details)
| WHERE ad LIKE "*Passkey (*" OR ad LIKE "*FIDO2 security key*"

// Pair each authentication method with its own success flag; event.outcome is sign-in level and is not tied to the passkey step
| GROK ad """"authentication_method":%{DATA:method_raw},"authentication_"""
| GROK ad """"succeeded":%{DATA:succeeded_raw}}"""
| GROK ad """"authentication_method_detail":%{DATA:detail_raw},"authentication_"""
| EVAL Esql.auth_methods = SPLIT(REPLACE(method_raw, """[\[\]"]""", ""), ","),
       Esql.auth_method_succeeded = SPLIT(REPLACE(succeeded_raw, """[\[\]"]""", ""), ",")
| EVAL Esql.method_outcome_pairs = MV_CONCAT(MV_ZIP(Esql.auth_methods, Esql.auth_method_succeeded, "~"), " || ")

// Require the passkey or FIDO2 step itself to have succeeded
| WHERE Esql.method_outcome_pairs LIKE "*Passkey (synced)~true*"
    OR Esql.method_outcome_pairs LIKE "*Passkey (device-bound)~true*"
    OR Esql.method_outcome_pairs LIKE "*FIDO2 security key~true*"

// Extract the provider and AAGUID from the authenticator detail
| EVAL Esql.auth_method_details = SPLIT(REPLACE(detail_raw, """[\[\]"]""", ""), ",")
| MV_EXPAND Esql.auth_method_details
| GROK Esql.auth_method_details """%{GREEDYDATA:provider_raw} - %{NOTSPACE:aaguid_raw}"""
| WHERE aaguid_raw IS NOT NULL AND (
    aaguid_raw == "00000000-0000-0000-0000-000000000000"
    OR NOT aaguid_raw RLIKE "[0-9a-fA-F]{8}-[0-9a-fA-F]{4}-[0-9a-fA-F]{4}-[0-9a-fA-F]{4}-[0-9a-fA-F]{12}"
  )
| EVAL Esql.passkey_aaguid = aaguid_raw, Esql.passkey_provider = provider_raw
| KEEP _id, _index, _version, @timestamp, azure.signinlogs.*, source.*, user.*, user_agent.*, event.outcome, Esql.*
