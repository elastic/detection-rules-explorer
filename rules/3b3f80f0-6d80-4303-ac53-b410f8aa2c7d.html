First-Seen Brotli-Compressed Chunked HTTP POST to Destination

Last updated a month ago on 2026-10-27
Created a month ago on 2026-10-27

About

Identifies the first destination IP observed receiving an HTTP POST request whose body is Brotli-compressed and transferred with chunked encoding. This combination can transport opaque application data while avoiding a fixed Content-Length, but it is not inherently malicious. Legitimate APIs, software distribution services, and custom clients may use the same encodings.

False Positive Examples
Legitimate APIs, mobile or desktop applications, backup and synchronization tools, content delivery workflows, and performance-sensitive custom clients may send Brotli-compressed request bodies with chunked transfer encoding. Validate the source application and destination service before escalating.
