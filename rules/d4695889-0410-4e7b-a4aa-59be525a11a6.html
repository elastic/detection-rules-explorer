Entra ID Register Device with Unusual User Agent

Last updated a month ago on 2026-10-26
Created 6 months ago on 2026-05-15

About

Detects successful, user-initiated Microsoft Entra ID audit events for Register device where additional details indicate an Azure AD join or Azure AD register and the recorded user agent is not one of the common native registration clients (Dsreg, DeviceRegistrationClient, or Dalvik-based Android enrollment). Legitimate Windows and standard mobile enrollment flows present predictable user-agent strings; unexpected clients such as axios, node, python-requests, or offensive tooling like GraphSpy and ROADtools may reflect scripted or adversary-driven device registration used to obtain a Primary Refresh Token for persistence or token abuse. Registrations performed by service principals or the Device Registration Service itself (for example Windows 365 Cloud PC pre-authorized joins) and Microsoft-owned EvoSTS authorization checks are excluded. Baseline approved provisioning tools and MDM integrations before tuning.

False Positive Examples
Custom device management agents, OEM enrollment clients, Linux Intune enrollment, or updated Microsoft clients that use new user-agent strings may match. Add exclusions for known `azure.auditlogs.properties.userAgent` values or enrollment programs after review.

azure.auditlogs.properties.initiated_by.user.id:* and
azure.auditlogs.properties.userAgent:(* and not (Dsreg* or DeviceRegistrationClient or Dalvik*)) and
azure.auditlogs.properties.additional_details.value:("Azure AD join" or "Azure AD register") and
not (azure.auditlogs.properties.userAgent:EvoSTS and source.as.number:8075)
